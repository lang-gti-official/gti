Run `gti --help` for the exact option list accepted by the installed version.
The command has two primary entry modes.

## Direct mode

```sh
gti src/main.gti -O2 -o app
```

Direct mode loads one entry source and its includes without consulting a
manifest. See [direct compilation](/tooling/cli/direct-compilation/) for
artifact, optimization, MIR, target-policy, and native-argument options.

## Project commands

| Command | Purpose |
| --- | --- |
| `gti build [target]` | Build one target, or every target with `--all`. |
| `gti check [target]` | Run frontend analysis without C++ emission or native compilation. |
| `gti run [target] -- args...` | Build and run one executable target. |
| `gti test [target]` | Build and run all test targets, or one named test target. |
| `gti new path` | Create a new executable package. |
| `gti init [path]` | Initialize an existing directory as a package. |
| `gti fetch` | Acquire pinned Git dependencies and write `gti.lock`. |
| `gti clean` | Remove only the active workspace's managed build subtree. |
| `gti metadata --format json` | Print deterministic project metadata. |
| `gti format init [directory]` | Create the default `.gti-format`. |
| `gti bindgen header.h` | Generate GTI declarations from a C header. |

Project command behavior and manifest examples are covered under
[projects and `gti.toml`](/tooling/projects/). Native header import has a
separate [`bindgen` reference](/tooling/bindgen/).
