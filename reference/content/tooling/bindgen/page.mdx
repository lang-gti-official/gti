GTI can call a deliberately bounded C ABI. `gti bindgen` uses Clang to parse
an existing C17 header and writes ordinary GTI `extern "C"`, `[[c_abi]]`, and
`[[c_opaque]]` declarations. Project manifests can run that same importer
automatically before source loading and compile or link the corresponding C
implementation.

Bindgen describes an ABI; it does not make a native library memory-safe,
infer ownership, or provide the implementation of imported symbols.

## Recommended project workflow

Use a manifest import when bindings belong to a GTI package. The complete
workflow has four parts:

1. a package-contained C header defining the imported surface;
2. `[bindgen.<alias>]` generating GTI declarations from that header;
3. a native source or library providing the declared C symbols; and
4. GTI source including `<alias/bindings>` and placing raw-pointer operations
   inside an `unsafe` boundary.

```text
counter-demo/
|-- gti.toml
|-- native/
|   |-- counter.c
|   `-- counter.h
`-- src/
    `-- main.gti
```

### 1. Declare the C boundary

```c
/* native/counter.h */
#ifndef COUNTER_H
#define COUNTER_H

#ifndef COUNTER_STEP
#define COUNTER_STEP 1
#endif

#define COUNTER_LIMIT (40 + COUNTER_STEP)

typedef struct Counter Counter;

Counter *counter_create(int start);
void counter_step(Counter *counter);
int counter_value(const Counter *counter);
void counter_destroy(Counter *counter);

#endif
```

An incomplete record is imported as an opaque handle. The implementation may
complete it privately:

```c
/* native/counter.c */
#include "counter.h"
#include <stdlib.h>

struct Counter {
  int value;
};

Counter *counter_create(int start) {
  Counter *counter = malloc(sizeof(Counter));
  if (counter != NULL) {
    counter->value = start;
  }
  return counter;
}

void counter_step(Counter *counter) {
  counter->value += COUNTER_STEP;
}

int counter_value(const Counter *counter) {
  return counter->value;
}

void counter_destroy(Counter *counter) {
  free(counter);
}
```

### 2. Generate and link from `gti.toml`

```toml
manifest-version = 1

[package]
name = "counter-demo"
version = "0.1.0"

[package.native]
c-sources = ["native/counter.c"]
c-compile-args = ["-DCOUNTER_STEP=2"]

[targets.counter-demo]
kind = "executable"
root = "src/main.gti"

[bindgen.counter]
header = "native/counter.h"
namespace = "counter_native"
defines = ["COUNTER_STEP=2"]
```

Bindgen `defines` affect only header preprocessing for the generated GTI
surface. `c-compile-args` independently affect the C implementation. A macro
that changes declarations or shared constants must be configured consistently
in both places.

### 3. Include and call the generated unit

```gti
#include <counter/bindings>

int main() {
  unsafe {
    mut counter_native::Counter* counter =
        counter_native::counter_create(40);
    if (counter == nullptr) {
      return 1;
    }

    counter_native::counter_step(counter);
    int32_t value = counter_native::counter_value(counter);
    counter_native::counter_destroy(counter);

    if (value != counter_native::COUNTER_LIMIT) {
      return 1;
    }
  }
  return 0;
}
```

```sh
gti check
gti run
```

`check`, `build`, `run`, and `test` generate manifest imports before loading
the target source. The generated unit is ordinary GTI source: normal source
visibility, C ABI validation, semantic diagnostics, HIR/MIR lowering, and
backend rules still apply.

## Manifest bindgen reference

```toml
[bindgen.library]
header = "native/library.h"
namespace = "library_native"
include-dirs = ["native/include"]
defines = ["LIBRARY_FEATURE=1"]
undefines = ["LIBRARY_LEGACY"]
allow = ["library_*", "LibraryState"]
deny = ["library_internal_*"]
rename = { library__state = "LibraryState" }
array-returns = [{ function = "library_items", count = "count" }]
```

| Field | Meaning |
| --- | --- |
| `header` | Required existing file, relative to `gti.toml` and contained by the package. |
| `namespace` | Optional ordinary GTI identifier wrapping generated source names. C link symbols remain unchanged. |
| `include-dirs` | Package-contained Clang header search directories. |
| `defines` | Ordered C preprocessor definitions in `NAME` or `NAME=value` form. |
| `undefines` | Ordered C preprocessor names to undefine. |
| `allow` | Import only exact names or prefixes written with one trailing `*`. |
| `deny` | Exclude matching exact names or prefixes; deny wins over allow. |
| `rename` | Rename imported types or constants whose C spelling is unsuitable for GTI. Functions cannot be renamed because their GTI name is their C link symbol. |
| `array-returns` | Declare that a function's pointer result contains the number of elements written through the named count parameter. |

Policy entries are checked. A pattern, rename, or array-return rule that
matches no declaration is reported rather than silently ignored. Excluded
declarations can still resolve types used by admitted declarations; a required
excluded record may be emitted as an opaque handle.

The alias must match `[A-Za-z_][A-Za-z0-9_]*`, cannot be `std`, and shares the
package include namespace with dependency aliases. The generated include is
always:

```gti
#include <library/bindings>
```

An import belongs only to its declaring package. Its alias does not leak to a
dependent package.

## Generation, reuse, and editor behavior

Generated declarations are published atomically at:

```text
build/gti/bindgen/<package>/<alias>/bindings.gti
```

The neighboring `bindings.key` covers the preprocessed translation unit,
including transitive headers, ordered import options, selected target triple,
and GTI tool identity. An unchanged import is reused without running the
in-process importer again. Editing a transitive header, changing policy,
changing target, or changing toolchain identity regenerates it.

A generated unit then participates in ordinary source-graph and whole-program
cache identity. `--verbose` prints successful reuse and importer notes;
generation is otherwise quiet on reuse. Preprocessor or import failures always
publish diagnostics.

The LSP resolves the generated include after a project `check` or build has
created it. Before the first generation, `<alias/bindings>` may be reported as
unresolved. Running `gti check` is sufficient; it generates bindings but does
not compile native C/C++ or link an executable.

Manifest generation selects Clang through `GTI_CLANG`, then `clang`. Unlike
the manual command, the manifest currently has no per-import `clang` or
`sysroot` field.

## What bindgen imports

The implemented importer covers:

- fixed-width-compatible C integer and floating values;
- C `long` according to the selected LP64 or LLP64 target data model;
- `const char*` as the non-owning GTI boundary type `c_string`;
- supported one-level raw pointers and pointer-qualified `const`;
- complete passive records as `[[c_abi]]` structs;
- incomplete or inexpressible records as `[[c_opaque]]` handles;
- enums as an `int32_t` alias with `constexpr` constants;
- object-like integer, floating, string, and character macros when their
  expressions are within the bounded evaluator;
- typedefs and named function-pointer callback aliases;
- fixed record-field arrays; and
- ordinary function prototypes in one `extern "C"` block.

The importer preprocesses the complete include graph once. Declarations from
the root header and user include directories are eligible for output.
Declarations from system headers are modeled but normally not emitted: their
typedefs and macro values can resolve admitted declarations, and a referenced
system record can be pulled in as an opaque handle. Diagnostics and skip
reports use the original header locations recovered from Clang line markers.

Every unsupported item appears in the generated file's `Not imported` report.
Skipped declarations are not compiler errors when the remaining generated
unit is coherent.

## Native implementation and linking

Generating declarations never supplies native symbols. Provide them with one
or more of:

- `c-sources` or `cpp-sources` compiled by the project;
- `link-files` naming an object or archive;
- `libraries` plus optional package-contained `library-dirs`;
- macOS `frameworks`; or
- bounded trusted exact argument fields where structured inputs cannot express
  the toolchain requirement.

```toml
[package.native]
include-dirs = ["native/include"]
c-sources = ["native/library.c"]
c-standard = "c17"
libraries = ["m"]
```

`include-dirs` used by native compilation and `include-dirs` under a bindgen
import are separate. Declare a directory in both places when both Clang
binding generation and native source compilation must search it.

GTI does not compare native definitions against generated declarations. A
mismatched calling convention, record layout, parameter type, target library,
or compile-time macro is an ABI bug in the application even if both sides
compile.

## Unsafe boundaries and safe wrappers

Raw native pointers do not gain ownership or lifetime from an imported
prototype. Dereferencing, indexing, taking addresses for C out parameters, and
calls whose admitted signature carries raw pointers remain lexical `unsafe`
operations. An opaque handle is nominal and pointer-only; it cannot be
constructed, inspected, or passed by value.

Keep the boundary narrow by placing native calls behind an ordinary GTI API
that validates arguments, establishes ownership, and guarantees cleanup. The
compiler recognizes the ABI rules, not a particular library name. Bindgen
does not infer that `counter_destroy` releases a `Counter*`, for example.

Callbacks are exact named native function types. Eligible captureless GTI free
functions can use the language's same-thread adapter rules; bindgen does not
invent userdata ownership or permit foreign-thread entry into GTI.

## Libcurl-style libraries

Directly importing a large C library is not always the best boundary. Libcurl
uses variadic functions such as `curl_easy_setopt`; C variadics are deliberately
not callable through GTI's bounded C ABI. Importing `curl/curl.h` therefore
cannot produce a complete high-level libcurl API.

Use a small fixed-signature C shim for the operations the GTI package needs:

```c
/* native/curl_shim.h */
#ifndef CURL_SHIM_H
#define CURL_SHIM_H

int curl_shim_get(const char *url);

#endif
```

```c
/* native/curl_shim.c */
#include "curl_shim.h"
#include <curl/curl.h>

int curl_shim_get(const char *url) {
  CURL *handle = curl_easy_init();
  if (handle == NULL) {
    return (int)CURLE_FAILED_INIT;
  }

  CURLcode option = curl_easy_setopt(handle, CURLOPT_URL, url);
  CURLcode result = option == CURLE_OK ? curl_easy_perform(handle) : option;
  curl_easy_cleanup(handle);
  return (int)result;
}
```

Bindgen sees only the stable, fixed-signature shim. The C compiler sees
libcurl's native header and owns the variadic calls:

```toml
[bindgen.curl_native]
header = "native/curl_shim.h"
namespace = "curl_native"

[package.native]
include-dirs = ["native"]
c-sources = ["native/curl_shim.c"]
libraries = ["curl"]
```

```gti
#include <curl_native/bindings>

int main() {
  int32_t result = curl_native::curl_shim_get("https://example.com");
  return result == 0 ? 0 : 1;
}
```

This manifest works when the C compiler and linker can already find libcurl in
their default search paths. For a project-contained distribution, add its
header and library directories through structured `include-dirs` and
`library-dirs`. A package-manager installation in an external prefix currently
requires explicitly trusted compiler/linker arguments or environment search
paths, which are less portable and conservatively bypass the whole-program
cache. GTI does not run `pkg-config` and manifest bindgen cannot name an
arbitrary external include directory through its contained `include-dirs`
field.

The shim is also the correct place to convert ownership, callback, variadic,
and version-specific C conventions into a small boundary that GTI can express
and test.

## Manual `gti bindgen`

Use the standalone command for inspection, one-off generation, or a binding
file intentionally checked into another project:

```sh
gti bindgen native/library.h \
  -o generated/library.gti \
  --namespace library_native \
  --target x86_64-unknown-linux-gnu \
  -I native/include \
  -D LIBRARY_FEATURE=1 \
  -U LIBRARY_LEGACY \
  --allow 'library_*' \
  --deny 'library_internal_*' \
  --rename library__state=LibraryState \
  --array-return library_items=count
```

Without `-o`, generated GTI is written to standard output. Repeated `-I`,
`-D`, and `-U` options preserve preprocessing order. `--target` selects the C
data model and defaults to the host. `--clang` selects the preprocessing
executable; otherwise the manual command uses `clang`. `--sysroot` forwards an
explicit platform SDK root when Clang cannot discover one. `-v` prints the
exact preprocessing command.

The standalone command generates a file only. It does not add a package source
root, modify `gti.toml`, compile a C implementation, or link a library.

## Diagnostics and troubleshooting

- A missing or package-escaping manifest header is rejected before generation.
- Alias and dependency collisions are manifest diagnostics because both use
  the same angle-include namespace.
- Clang preprocessing failures retain the native header location and output.
- An importer failure identifies the `[bindgen.<alias>]` declaration; detailed
  reader and planner notes identify the original C declaration.
- Unsupported declarations remain listed in generated source even when the
  usable subset builds successfully.
- Linker `undefined symbol` errors mean declarations were generated but their
  native implementation or library was not supplied for the selected target.
- A stale generated include after changing headers should regenerate on the
  next `check` or build. `-v` distinguishes generated and reused imports.
- On macOS, the manual command's `--sysroot` can select an SDK. Manifest imports
  currently rely on the selected Clang's own SDK discovery.

## Deliberate limits

C++ declaration import is not implemented. C variadics, native variables,
arbitrary nested pointers, implicit ownership transfer, flexible array
members, unsupported calling conventions, assembler link-name overrides, and
layout-altering attributes are skipped or conservatively degraded where the
language can still represent pointer-only use.

GTI ordinary classes, templates, overloads, exceptions, and C++ linkage do not
have a stable foreign ABI. Use a C17 boundary, passive `[[c_abi]]` records,
opaque handles, and fixed-signature wrapper functions.
