GTI ships one compiler pipeline behind a small set of command-line and editor
tools. Direct compilation is useful for a single source entry. Project mode
adds manifests, named targets, profiles, dependencies, caching, and native
inputs without changing the language compilation rules.

## Tooling map

| Area | Use it for |
| --- | --- |
| [`gti` command line](/tooling/cli/) | Direct compilation and project commands. |
| [Projects and `gti.toml`](/tooling/projects/) | Reproducible packages, targets, profiles, workspaces, and dependencies. |
| [C bindgen and native interop](/tooling/bindgen/) | Generate bounded C declarations, compile native sources, link libraries, and design safe wrappers. |
| [Formatter](/tooling/formatting/) | Configure the LSP's syntax-aware source formatter. |
| [Language server](/tooling/lsp/) | Diagnostics, navigation, semantic highlighting, completion, and formatting. |

Compiler diagnostics and language meaning come from the same frontend in
direct builds, project builds, and the language server. Tooling should not
invent a second interpretation of GTI source.
