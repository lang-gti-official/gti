```gti
#include <std/memory>
```

Typed storage allocation is recoverable and returns `expected`; it does not
expose `new`, `delete`, an allocation address, or an unchecked deallocation operation.
`std::storage<T>` owns a fixed number of independently initialized slots and
drops every remaining live value before releasing the allocation.

`std::arena<T>` adds monotonic positions and invalidates all prior positions
on `reset()`. `std::pool<T>` reuses erased positions; a numeric position names
a slot rather than a permanent object identity. References returned by either
owner are receiver-tied and prevent overlapping mutation through ordinary
borrow rules.

`std::unique_ptr<T>`, `std::make_unique<T>`, and
`std::upcast_unique<Base, Derived>` are implemented in this unit and are not
part of the implicit prelude. `std::shared_ptr`, `std::weak_ptr`, and
`std::make_shared` are still declaration-only and are excluded from the
executable synopsis.

Empty `unique_ptr` dereference or arrow access, including mutable access,
reports `GTI-R0008` after normal cleanup. Its source site is the checked
operation in `<std/memory>`. `make_unique` allocates class/struct objects and
scalar values. A scalar initializer must match `T` exactly. Numeric, boolean,
character, and raw-pointer values also support zero/null initialization with
no argument; plain enums, `nullptr_t`, and native callbacks need an explicit
value. Allocating a raw pointer does not acquire ownership of its pointee.

Unlike typed storage allocation, `make_unique` does not return `expected`.
Scalar exhaustion reports `GTI-R0011` after normal cleanup. Class allocation's
failure cleanup and fallible-constructor rollback are still incomplete.
